# Contributing to Reno

If you find any bugs while using Reno, or believe there's a feature that would
prove useful, feel free to submit an appropriate
[issue](https://github.com/ORNL/reno/issues/new).

If you have a question, double check that it's not answered in our
[documentation](https://ornl.github.io/reno/stable/), and if not feel free to
open an issue for your question.

# Submitting a PR

If you have added a useful feature or fixed a bug, open a new pull request with
the changes. When submitting a pull request, please describe what the pull
request is addressing and briefly list any significant changes made. If it's in
regards to a specific issue, please link to that issue in the text.

## AI Policy

The wording of this policy is taken in part from [NumPy](https://numpy.org/devdocs/dev/ai_policy.html), [NixOS](https://github.com/NixOS/nixpkgs/blob/master/CONTRIBUTING.md#automationai-policy), [scikit-learn](https://scikit-learn.org/dev/developers/contributing.html#automated-contributions-policy), and [ibis](https://ibis-project.org/contribute/06_automated_code_and_ai)

### Responsibility

You are responsible for any code you submit for Reno, regardless of whether it was manually written or generated by AI. You must understand and be able to explain the code you submit as well as the existing related code. Do not submit AI-generated code that you haven't personally reviewed, understood, and tested. Code should ideally be brief, recognize when less is more, and do your best to follow the conventions and standards of the project.

### Disclosure

You must disclose whether AI has been used to assist in the development of your code. If so, you must document which tool(s) have been used, how they were used, and ideally specify what code or text is AI generated.

Use of AI tools for research, brainstorming, and debugging does not need to be disclosed if no substantial amount of their output is included in the resulting contribution. However, if these tools had a significant technical influence on your contribution, you are still responsible for it per the Responsibility section, and are expected to disclose this where relevant.

This disclosure may occur within commit messages, pull request descriptions, and/or separate markdown files included in the contribution. Per the Communication section, these disclosures should be in your own words, rather than generated/summarized with an LLM.

### Communication

When interacting with developers do not use AI to speak for you, except for grammar editing. Please do not paste AI generated text in the description of issues, PRs, or in comments. Descriptions, comments, and reviews must separately satisfy the same requirements of understanding, review, and disclosure.
